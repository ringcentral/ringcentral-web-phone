# Enable Trickle ICE by default while retaining SIP ownership

RingCentral confirmed server support for the client-to-server Trickle ICE flow exercised by this SDK. SDK-managed WebRTC therefore uses Trickle ICE by default, without a public enablement option, for every local ICE generation, including initial call establishment, re-INVITEs, and ICE restarts. Delegated WebRTC may opt in through one optional `trickleIce` capability with `setLocalCandidateHandler` and `addRemoteCandidate`; implementations without that complete capability retain complete-SDP behavior. Candidate data uses the browser-standard `RTCIceCandidateInit` shape, with `null` marking the end of a generation. The SDK sends generated SDP immediately, omits candidates already present in the sent SDP from later INFO requests, and sends one candidate per serialized INFO request followed by end-of-candidates. The SDK converts an incoming SDP fragment once into browser-shaped candidate data, preserves each candidate value, and holds candidates until the remote description is ready; ordinary candidate validity and media or generation matching belong to browser WebRTC or the delegated application, while the SDK retains generation protection for `null` end markers. A capable Call Session advertises `Supported: trickle-ice`; a delegated implementation that opts in must return SDP containing `a=ice-options:trickle`, and the SDK fails clearly rather than rewriting inconsistent delegated SDP. The SDK owns SIP INFO construction and dialog signaling rather than exposing SIP details to applications. Incoming candidate INFO retains the SIP client's automatic `200 OK`; candidate application is asynchronous and a failure may warn in debug mode but does not fail the Call Session. Likewise, if an outgoing candidate INFO fails, the SDK stops trickling that ICE generation and may warn in debug mode; it does not fail the Call Session or initiate a fallback re-INVITE. The supported scope is the RingCentral audio calling subset. No Web Phone option, Call Session event, or manual candidate-sending method is added; the delegated capability is the only new public interface.
